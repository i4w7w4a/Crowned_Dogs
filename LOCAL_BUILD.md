# Crowned Dogs: Windows и браузер

Оба варианта запускают одну игру и используют одно ядро Rust, собранное в WebAssembly. Окно Windows использует Tauri 2 и системный WebView2. Браузерный вариант работает в обычном браузере с WebGL 2. Это не отдельный рендер на Vulkan: Three.js продолжает рисовать утверждённые модели и интерфейс.

## Готовая локальная сборка

В папке `release-local/Crowned-Dogs/`:

- `CrownedDogs.exe` — отдельное окно игры.
- `CrownedDogs-Web.exe` — локальный сервер и открытие игры в браузере.
- `game/` — игра, WASM, модели, изображения, музыка и звуки. Оставлять рядом с программами.
- `MANIFEST.json` — размеры и SHA-256 файлов этой сборки.

Закройте первый вариант перед запуском второго: оба занимают `127.0.0.1:5197`. Сервер доступен только на этом компьютере. В браузерном варианте закрытие окна сервера останавливает игру. Если браузер не открылся автоматически, адрес — `http://127.0.0.1:5197/`.

Для Windows-программы нужен установленный [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/). Обычный браузерный вариант не требует WebView2. Комплект и настройки сохраняются отдельно в браузере и в окне программы.

Сборку со звуками Sonniss держать закрытой. Не распространять звуковые файлы отдельно от игры.

## Подготовка исходников

Нужны Git, Node.js 22.18+ и [Rust через rustup](https://www.rust-lang.org/tools/install). Для сборки Windows-программы также нужны Visual Studio Build Tools с компонентами C++ и Windows SDK. В `rust-toolchain.toml` выбран stable с `wasm32-unknown-unknown`; зависимости зафиксированы в `Cargo.lock` и `package-lock.json`.

Из корня репозитория:

```powershell
npm ci
rustup update stable
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.129 --locked
npm run rust:build
```

Версия `wasm-bindgen-cli` должна совпадать с зависимостью `wasm-bindgen` в `crates/game-wasm/Cargo.toml`. При обычной установке rustup команды доступны после открытия нового терминала. Скрипт сборки также ищет их в домашней папке `.cargo/bin`.

Сгенерированный пакет `packages/runtime/wasm/` не хранится в Git. После чистого клонирования его обязательно надо собрать. Это нужно и для Telegram-бота, тестов и расчёта баланса: они используют тот же Rust/WASM. Повторная сборка инкрементальная.

## Сборка и запуск

```powershell
# Разработка в браузере; адрес выведет Vite
npm run web

# Только готовая браузерная папка apps/web/dist/
npm run web:build

# Две Windows-программы и общая папка game/
npm run local:build
```

`local:build` предназначен для Windows. `web` и `web:build` работают также на Linux/macOS. Браузерную сборку надо отдавать по HTTP с корректным типом `application/wasm`; открытие `index.html` двойным щелчком через `file://` не поддерживается. Готовые Windows-программы поднимают такой сервер сами.

Для Telegram нужны также `.env` и токен бота, как описано в `README.md`. После `npm run rust:build` доступны `npm run bot`, `npm run balance` и `npm run kits`.

## Что исполняется на Rust

| Модуль | Область |
| --- | --- |
| `crates/game-core` | Правила боя, RNG, команды и ход, AI, характеристики, каталог, комплекты и жетоны |
| `crates/game-client` | Локальная дуэль, выбор снаряжения и обвесов, серверные дуэли и контракты, тексты, качество графики, музыкальные сценарии, выбор звуков и DSP |
| `crates/game-motion` | IK, позы, отдача, темп ходьбы, падения, последовательность анимаций, расчёты частиц и камеры просмотра |
| `crates/game-graphics` | Подиум и карты его материалов, камера примерочной, ремень, видимость обвесов, данные для параллакса |
| `crates/game-ui` | Состояния боевых кнопок, раскладка, кольца атаки, каталог, лог, итог боя и геометрия SVG-иконок |
| `crates/game-wasm` | Общий интерфейс; в `src/browser/` — контроллеры экранов, события DOM, просмотр моделей, арена, проходы рендера, загрузка текстур и WebAudio |
| `apps/desktop` | Окно Windows и локальный HTTP-сервер с поддержкой диапазонов аудиофайлов |

Баланс и каталог теперь находятся в `crates/game-core/catalog/catalog.json`. TypeScript в `packages/core/src/` — типизированные вызовы Rust. `packages/core/reference/` и `crates/game-motion/reference/` — зафиксированные версии для сравнения поведения и типов; игровая сборка не исполняет их как запасной движок.

В TypeScript остаются типы и тонкие адаптеры импортов внешних библиотек. Маршрутизация, Telegram-обработчики, хранение состояния, таймеры, загрузка, создание объектов Three.js, анимация, материалы, звук и освобождение ресурсов управляются Rust через wasm-bindgen. Three.js и браузерные API продолжают выполнять отрисовку и вывод звука. CSS сохраняет внешний вид. Шейдеры исполняются на GPU на GLSL и учитываются как GLSL. Rust/WASM обязателен для работы игры.

### Как измеряется доля Rust

`npm run source:share` считает непустые строки рабочих исходников, включая комментарии, одним и тем же способом для прежней и новой версии. В знаменатель входят Rust, TypeScript, HTML, CSS и GLSL; тесты, старые эталоны, отдельные файлы `.d.ts`, сгенерированные файлы, сборки и зависимости исключены. Интерфейсы внутри обычных `.ts` учитываются. JSON-каталоги — отдельные данные. Это показатель состава исходников, не скорости и не объёма выполненной работы. Rust форматируется обычным rustfmt.

Исходный замер — 6394 из 14729 строк, **43,41%**. Его можно воспроизвести: `node tools/source-share.mjs --ref 9266f893ab87c5cb2c4ba7b625e68af5654c5c46`. Команда без `--ref` измеряет текущие файлы, включая ещё не закоммиченные исходники. В отчёте отдельно показан весь репозиторий: там старый TypeScript намеренно сохранён для проверок совпадения поведения.

После переноса 30 октября, до объединения с проекционной сценой боя, замер составлял **22569 из 25075 строк — 90,01% Rust** (предыдущий этап — 78,96%). После объединения: **23428 из 25980 строк — 90,18% Rust**. Остальные рабочие исходники: 1185 строк TypeScript, 561 CSS, 231 HTML и 575 GLSL/vertex/fragment (530 + 36 + 9). Методика подсчёта не менялась. Прежние реализации сохранены в `crates/game-wasm/reference/browser90/` и `reference/browser90/` для сравнения; игровая сборка их не импортирует.

В объединённой сборке `npm run check` проверяет 169 сценариев Node/WASM: 168 проходят, один тест принудительной сборки мусора пропускается в обычном запуске. Отдельный `node --expose-gc --test apps/web/test/browser-app-rust.test.ts` проходит 5/5, включая этот сценарий. `npm run rust:check` проходит 39 нативных тестов. `npm run test:render` включает четыре прежние проверки рендера, две новые группы проекционной сцены, восемь проверок анимации/IK и отдельный набор для сцены: геометрия, модели, авторский ремень, материалы, POM и тени, отмена загрузки, освобождение ресурсов. Дополнительные проверки сравнивают точные пиксели liquid glass, граф/сэмплы радио и DOM журнала с эталоном. Закрытие приложения отменяет загрузку и предотвращает поздний запуск боя. Главное приложение удерживается в Rust до явного unmount; проверка с реальным GC не позволяет ему исчезнуть из production-сборки.

До объединения браузерная сборка была проверена без звука при 1280×720 и 390×844: база, примерочная, каталог, оружие, возврат в прежний каталог, ход боя, меню и выход. Дополнительно был проверен подиум с Silhouette POM на высокой графике. Эта историческая проверка размеров не подтверждает проверку текущей объединённой сборки на телефоне и не является тестом физического устройства или отдельного окна WebView2.

Для объединённой версии успешно выполнены `npm run web:build` и `npm run local:build`. `node tools/local-smoke.mjs` проверил хэши 264 файлов локального пакета, выдачу 261 HTTP-ресурса, WASM MIME, аудиодиапазоны и ограничения путей/Host.

## Camera Projection Mapping в бою

В главную также добавлена [проекционная база](tools/base-stage/README.md): проезд к короне перед боем и через туннель перед экраном «Снаряжение». После этого этапа доля Rust составляет 23864 / 26436 рабочих строк, 90,27%. Добавлены две проверки реальных Rust-контроллеров камеры и переходов; всего 171 Node/WASM-сценарий (170 проходят в обычном запуске, GC-сценарий — отдельно с `--expose-gc`). Предыдущие численные результаты выше относятся к моменту первоначального объединения.

Первый соляной цех (`hall1`) использует 53 меша и 3264 треугольника: пол, стены, кровлю и отдельные объёмы оборудования. Фотографии проецируются с неподвижной исходной камеры на эту геометрию. При собственном ходе бойца сцена перемещается относительно игровой камеры на рассчитанное расстояние в метрах; ближние предметы и дальние стены дают разный параллакс. Если движется только противник, камера и окружение остаются на месте. Второй фон (`hall2`) сохранён без этой замены.

Продольный проезд построен на геометрии, а не на смещении карты глубины. За границами исходного кадра поверхности продолжаются отдельными текстурами пола, стен и кровли. Фиксированная проекция рассчитана на движение вперёд и назад, а не на свободный круговой обзор завода. Актуальная глубина геометрии используется для дымки и глубины резкости; ближние конструкции перекрывают бойца, а пол не отсекает его отражение.

Контроллер сцены и жизненный цикл ресурсов находятся в `crates/game-wasm/src/browser/projected_stage.rs`; TypeScript передаёт только Three.js и рендерер. Геометрия и материалы лежат в `apps/web/public/img/battle-stage/`, воспроизводимый Blender-скрипт — в `tools/battle-stage/`. Эта сцена входит в общий браузерный и Windows-пакет вместе с Rust-контроллерами, примерочной и POM.

## Silhouette POM

На средней, высокой и максимальной графике верхняя плита подиума использует поиск пересечения с полем высоты, обрезку контура и запись найденной глубины. Тени используют согласованный проход. На низкой графике остаётся обычная 3D-плита с текстурой и bump map.

Оригинальные модели шлема, костюма, бронежилета и оружия не изменены. Отдельный [инструмент Rust](tools/height-baker/README.md) восстановил из normal maps 20 наборов карт микрорельефа: все стволы («Варяг», «Пустельга», «Таран», «Беркут»), все модули «Варяга», шлем, жилет и костюм. Карты 1024×1024, 16-битные мастера и маски UV-швов лежат в `apps/web/public/tex/relief/`. Это приближённый микрорельеф, не точное восстановление крупной геометрии и не high-poly bake.

Для оружия, шлема и жилета доработан **surface POM v2**: физический масштаб глубины, самозатенение от реальных источников света, швейные каналы и плетение ткани. Он включён при средней графике и выше; для сравнения с исходником добавьте `?relief=0` перед `#weapon` или `#fitting`. Контрольная поверхность сверена с объёмной геометрией на GPU. Снимки, отчёт и команды: [review-v2](docs/relief/review-v2/README.md). Костюм остаётся исследовательским; у авторской Персоны доработка подключена к проверенному жилету. Геометрический силуэт сохраняется; Silhouette POM остаётся на подиуме.

## Проверки

```powershell
npm run check
npm run web:build

# Rust-библиотеки — подходит Windows/Linux/macOS
cargo test --locked --release -p game-core -p game-client -p game-motion -p game-graphics -p game-ui

# Весь workspace, включая Windows-программу — на Windows
npm run rust:check

# Сравнение математики примерочной с прежней реализацией
node crates/game-graphics/tests/parity.mjs

# Сравнение проходов рендера, текстур и жизненного цикла арены
node tools/test-render-orchestration.mjs

# Доля Rust в рабочих исходниках
npm run source:share

# Численная проверка генератора карт высоты
cargo test --manifest-path tools/height-baker/Cargo.toml --release --locked

# Проверка уже запущенной локальной сборки: файлы, WASM, аудио и пути
node tools/local-smoke.mjs
```

Команды `check`, `test`, `typecheck`, `web`, `web:build`, `bot`, `balance` и `kits` автоматически обновляют WASM перед запуском. Перед прямым вызовом отдельного файла через `node` надо выполнить `npm run rust:build`, если WASM отсутствует или Rust-код менялся.

`npm test` проверяет Rust через настоящую границу WASM, в том числе совпадение поз и анимаций с прежним клиентом. Нативные тесты сравнивают игровые правила с замороженным эталоном: функции, RNG и полные бои. Генераторы эталонов не следует автоматически запускать после изменения баланса.

Все ручные проверки игры проводить без звука: добавить `?muted=1` перед `#fitting`, `#weapon` или другим маршрутом. Например: `http://127.0.0.1:5197/?muted=1#fitting`. Этот режим не создаёт аудиоконтекст и не меняет сохранённые звуковые настройки. Windows-программу можно запустить с аргументом `--muted`. Для фонового запуска браузерного сервера без открытия вкладки есть `CrownedDogs-Web.exe --no-open`.

При запущенном Vite страница `/pom-check.html` показывает подиум под разными углами и проверяет GPU-буфер глубины/теней. Она предназначена для разработки и не входит в готовую игру. Успешные модульные тесты не заменяют просмотр боя и примерочной на телефоне и ПК.

Документация wasm-bindgen, Tauri 2 и Three.js сверялась через Context7 при переносе.
