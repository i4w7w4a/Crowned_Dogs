# Сетевой 3D-клиент

Направление #19 эпика #16. Клиент использует согласованный контракт v1 сервера #18 и вход через Telegram #20.

## Путь игрока

Mini App отправляет подписанный `initData` на `/auth/telegram`. Сайт использует текущую сессию или browser challenge: явный вход → ссылка в бота → подтверждение → status → одноразовый consume. Без серверного аккаунта база не открывается. `initDataUnsafe` используется только для token приглашения, никогда для личности.

Официальный WebApp SDK загружается в `<head>`. После успешной server auth клиент запоминает только SHA-256 от initData и account ID в sessionStorage, с ключом по API base. Если тот же payload устарел, действующая cookie может восстановить только тот же аккаунт через `/me`. Другой payload/account либо отсутствующая cookie требуют заново открыть Mini App. Серверный TTL не ослабляется, сырые credentials не сохраняются.

Ссылка `?invite=…` и `startapp=duel_…` сохраняются в sessionStorage через вход. Карточка требует явного принятия. Собственный вызов можно отменить; ошибку Telegram-доставки — повторить с тем же token. Группу и тему выбирает оператор сервера.

Клиент принимает только 32-символьные URL-safe invite tokens. Повреждённое значение из ссылки или старого storage не блокирует browser challenge; валидное приглашение сохраняется при истечении подтверждения и новом входе.

Профиль, внешность, комплект и очки читаются из `/me`. Локальные `cd-sync` и комплекты не подменяют серверный профиль. Сохранение отправляет намерения `spend/appearance/equip/mod/paint`, ждёт подтверждения и показывает ошибку. Во время записи повторный ввод заблокирован. Графика, звук и кэш остаются на устройстве.

## Бой и восстановление

- `RemoteDuel` хранит только публичную проекцию и отправляет HTTP-команды; локальные botOrder, resolveTurn, timeout и syncGain в сетевом пути не вызываются.
- Сначала открывается доступное для ввода лобби. После выбора серверного матча запускаются модальный загрузчик и 3D. Отмена возвращает базу; поздний ответ после dispose не запускает бой. Retry загрузки использует уже выбранный матч.
- `client.online.view` в Rust переводит canonical side в local0: оба бойца и их комплекты, config, отчёты, атаки, перемещения, защита, HP, AFK/stun, lane, координаты/попадания опасностей и победитель. Положительное перемещение остаётся движением к противнику; ось lane отражается.
- `ready` уходит после загрузки 3D и двух нарисованных кадров. Гонка двух ready восстанавливается через GET и новый запрос готовности, если сервер ещё не подтвердил свою сторону.
- Таймер показывает `deadline - serverNow` с монотонным временем браузера. Меню не останавливает его; клиент никогда не разрешает ход по своему таймеру.
- Один следующий подтверждённый отчёт проигрывается. Reload, возвращение из скрытой вкладки и несколько пропущенных ходов восстанавливают текущий снимок и журнал. Poll не подменяет проекцию во время команды или анимации.
- Мутация записывается в sessionStorage **до** отправки. Потеря ответа повторяет прежние body и UUID; definite HTTP-отказ очищает квитанцию. Очередь привязана к account ID, чтобы вход другим аккаунтом не повторял чужое намерение.
- Выход на базу оставляет бой активным. «Сдаться» требует явного подтверждения и отправляет отдельную серверную команду. Отладочные смены карты, оружия, времени и погоды в PvP отключены.
- Финал показывает серверный `reward`; повторный показ не начисляет опыт. Последний бой запоминается до выхода с просмотренного финала, включая бой, завершившийся при закрытой странице.
- Две Персоны одного пола получают собственные материалы до применения внешности. Геометрия и неизменяемые текстуры остаются общими; материалы примерочной не заменяются.

## Проверка

`npm run check`, `npm run web:build`, `cargo test -p game-client -p game-wasm`.

Новые проверки: отражение стороны, выбор перемещения без повторного переключения, намерения профиля, устаревшие ответы, resume/gap, публичные серверные fixtures, потеря ответа/reload/смена аккаунта и реальные Three.js материалы двух Персон каждого пола. Существующие beard-loading и render/motion/scene suites сохраняются.

Для видимой проверки есть отдельный процесс `node tools/online-client-preview.mjs` (сторона 1, loopback 5180) и `--side0` (сторона 0, loopback 5179). Он воспроизводит **публичные снимки** настоящего Rust reducer из серверного коммита `ad0b6e0`; не моделирует полноценный серверный матч. Тестовых маршрутов, cookie-выдачи или bypass входа в production bundle нет. Открывать с `?muted=1`, для слабого устройства — `&q=low`.

Проверены desktop и 390×844: обе стороны, две male-Персоны с разными skin/face/suit, выбор приказа, запреты меню, проигрывание сохранённого отчёта и серверный итог. Снимки: `research/online-client/`.

Путь двух изолированных браузеров через настоящие API, native PostgreSQL, reload, restart между приказами и повтор финала проверен на общей сборке; подробности и ограничения — в `docs/online-client-evidence.md`. Подписи пользователей были синтетическими. Два человеческих Telegram-аккаунта, доставка в живой игровой чат и browser bridge с настоящим ботом остаются отдельной приёмкой #21. Этот PR не включает production и не утверждает готовность всего онлайн-выпуска.
